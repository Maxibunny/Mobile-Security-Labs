# Автоматический запуск лабораторной №2 на Windows

## Самый простой способ

1. **Полностью распакуйте ZIP**. Не запускайте `.cmd` из предварительного просмотра ZIP-архива: там не будут видны `gradlew.bat`, `notes/`, `client/` и `scripts/`.
2. В Проводнике откройте **`2lab`** — папку, внутри которой лежат `START_LAB2.cmd` и `settings.gradle.kts`.
3. Дважды нажмите **`START_LAB2.cmd`**. Терминал откроется **сам**. PowerShell, команды `adb install` и Git Bash вручную не нужны.
4. Ждите завершения; окно **не закрывается само**, даже если обнаружена ошибка. Прочитайте последние строки.
5. При ошибке отправьте `logs/auto-.../summary.txt` и файл команды, на которой всё остановилось.

После первой успешной сборки для быстрой повторной установки и проверки используйте **`CHECK_LAB2.cmd`** — сборка и инструментальные тесты будут пропущены. Проверка преподавателя (`check.sh all`) останется.

## Исправление 21.10.2026: неверное определение результата Gradle

Если Gradle в логе выводит `BUILD SUCCESSFUL`, но старый скрипт сообщает
`gradle_build: exit code` **без числа** и затем ошибочно пишет «Gradle не собрал два APK»,
значит ошибка была **в автоматизаторе**, а не в сборке Notes.

В этой версии `Invoke-Tool` запускает команды через `System.Diagnostics.Process` и
читаeт числовой `ExitCode` после завершения процесса. Выводы stdout/stderr
параллельно считываются асинхронно, чтобы не блокировать Gradle или ADB.
Перед сборкой проводится короткая проверка механизма запуска.

Для отдельной проверки без Android SDK/эмулятора дважды откройте **`SELFTEST_LAB2.cmd`**.
Должно появиться `SELFTEST PASSED` — код 0 принят как успешный, код 7 распознан
как ошибка. Проверка 7 намеренно создаёт предупреждение о ненулевом коде — это
ожидаемая часть теста, а не проблема проекта.

После успешной самопроверки откройте **`START_LAB2.cmd`**. Если APK уже собраны
и хочется только установить их и выполнить преподавательский скрипт,
используйте **`CHECK_LAB2.cmd`** (не пересобирает APK).

**Статус проверки:** ранее пользователь получил `BUILD SUCCESSFUL` для обоих
модулей. Исправленная версия PS1 статически проверена, однако реальный прогон
на Windows и эмуляторе нужно подтвердить логами именно с этого компьютера.

## Что выполняется автоматически

```text
START_LAB2.cmd
  -> scripts/auto_run_windows.ps1
      -> найти Android SDK, adb и JDK
      -> gradlew.bat :notes:assembleDebug :client:assembleDebug
      -> обнаружить запущенный эмулятор или запустить первый созданный AVD
      -> getprop sys.boot_completed + проверка PackageManager
      -> adb install --no-streaming -r notes-debug.apk
      -> adb install --no-streaming -r client-debug.apk
      -> проверить, что обе программы установлены
      -> Git Bash: bash scripts/check.sh all (если Git Bash найден)
      -> :notes:connectedDebugAndroidTest (если доступна инструментальная сборка)
      -> adb shell am start -n ...MainActivity (оба приложения)
      -> сохранить реальный вывод команд в logs/auto-.../
```

Первая сборка и запуск Android могут занимать несколько минут: это зависит от компьютера, SDK и необходимости загрузки Gradle-зависимостей. Отдельные команды имеют тайм-аут: зависший `adb shell` проверяется и сценарий пытается перезапустить ADB. Если эмулятор вообще перестал отвечать, сценарий пробует штатно остановить **именно его** через `adb emu kill` и холодно запустить AVD без сброса данных; при неудаче завершает сценарий с диагностикой.

**Скрипт НЕ вызывает** `Wipe Data`, `adb uninstall`, очистку базы Room или принудительное завершение сторонних процессов. `adb install -r` сохраняет данные установленного приложения при совпадающих подписях. Если клиент был ранее установлен с другим сертификатом и Android отверг обновление, скрипт остановится, не удаляя данные.

## Что нужно уже иметь на компьютере

- **Android Studio и Android SDK** с `platform-tools/adb.exe` и SDK Platform 36. У вас они есть, если `adb devices` и сборка уже работали.
- **Созданный виртуальный телефон (AVD)**. Если AVD нет, один раз откройте Android Studio → Tools → Device Manager → **+** → Create Virtual Device → Pixel 6 → API 36 → Finish. После этого двойной щелчок по CMD запустит его самостоятельно.
- **JDK**. Используется `JAVA_HOME`, а при его отсутствии скрипт ищет встроенный JBR Android Studio.
- **Git for Windows** — для запуска исходного `bash scripts/check.sh all`.
- **Android SDK Command-line Tools (latest)** — для инструмента `apkanalyzer`, необходимого чек-листу преподавателя. В Android Studio: Tools → SDK Manager → SDK Tools → Android SDK Command-line Tools (latest) → Apply.

Нужен интернет при первой загрузке Gradle и зависимостей; эмулятору может понадобиться аппаратная виртуализация. Никакой скрипт не способен автоматически устранить отключенную виртуализацию BIOS или отсутствующий system image, не получив от пользователя необходимых прав/согласия.

## Где посмотреть результаты

- `logs/auto-YYYYMMDD-HHMMSS/summary.txt` — тайминги, шаги, ошибки и предупреждения.
- `logs/auto-.../NNN-gradle_build.stdout.txt` / `.stderr.txt` — фактический Gradle-лог.
- `logs/auto-.../NNN-install_*.stdout.txt` — подлинный вывод установки APK.
- `logs/auto-.../NNN-security-check.stdout.txt` — **реальный** результат официального `scripts/check.sh all`; его копия сохраняется в `docs/evidence/check-all.txt`.
- `logs/auto-.../NNN-instrumented-tests.*` — инструментальные тесты, если удалось их запустить.

В отчёте НЕ подставляются шаблонные `PASS`: строки `PASS` появляются только при фактическом выполнении `check.sh`. Все журналы в `logs/` исключены из Git, так как могут содержать локальные пути/данные устройства. Перед публикацией `docs/evidence/check-all.txt` проверьте, что там нет приватных данных.

## Что делать при проблемах

| Сообщение | Причина и действие |
|---|---|
| `Android SDK не найден` | В Android Studio → Tools → SDK Manager проверьте SDK Location. Если SDK в нестандартном каталоге, добавьте `sdk.dir=C:/.../Android/Sdk` в локальный `local.properties` (он не коммитится). |
| `Gradle не собрал два APK` | Откройте `NNN-gradle_build.stderr.txt` и `NNN-gradle_build.stdout.txt`. Возможны нехватка интернета, неверный JDK, сломанные зависимости или ошибки кода. |
| `Нет созданного виртуального телефона` | Создайте AVD один раз в Device Manager. |
| `Эмулятор не отвечает` | Сценарий не висит бесконечно. Завершите зависший эмулятор через Device Manager и затем снова откройте `START_LAB2.cmd`; для тяжёлых случаев можно воспользоваться Cold Boot Now. Не нажимайте Wipe Data. |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | Уже установленное приложение подписано другим ключом. Скрипт **не удаляет** его ради сохранности данных. Перед удалением сохраните нужные данные самостоятельно. |
| `Git for Windows не найден` | Установите Git for Windows (`https://git-scm.com/downloads/win`). Основные APK могут успешно установиться, но преподавательская проверка будет пропущена с предупреждением. |
| `apkanalyzer не найден` | Android Studio → Tools → SDK Manager → SDK Tools → Android SDK Command-line Tools (latest). |
| `scripts/check.sh all` вернул ненулевой код | Это не обязательно проблема сборки: прочтите реальный `docs/evidence/check-all.txt` и устраните конкретный `FAIL`. |
| `connectedDebugAndroidTest` завершились ошибкой | Пришлите `NNN-instrumented-tests.*`; это дополнительная проверка, а не замена скрипта преподавателя. |

## Необязательные режимы

Из PowerShell в папке проекта (только если нужно, обычному пользователю достаточно CMD-файлов):

```powershell
# Полный цикл:
.\scripts\auto_run_windows.ps1

# Без сборки:
.\scripts\auto_run_windows.ps1 -NoBuild

# Не запускать дополнительные инструментальные тесты:
.\scripts\auto_run_windows.ps1 -SkipInstrumentedTests

# Пропустить Bash-проверку (для диагностики установки, НЕ для сдачи):
.\scripts\auto_run_windows.ps1 -SkipSecurityChecks
```

Если PowerShell запрещает прямой запуск `.ps1`, используйте основной `START_LAB2.cmd`: он передаёт `ExecutionPolicy Bypass` **только созданному процессу PowerShell** и не меняет политику безопасности системы.

## Границы подтверждения

Статический аудит исходников запускается командой `python scripts/static_audit.py`. Сборка обоих модулей ранее была подтверждена сообщением пользователя `BUILD SUCCESSFUL` (21.10.2026). Автоматический CMD/PowerShell сценарий создан и проверен структурно, но **не исполнялся в Windows и на Android-эмуляторе в среде подготовки этого архива**. Поэтому работоспособность автосценария и результат `scripts/check.sh all` должны быть подтверждены первым запуском на реальном компьютере.
