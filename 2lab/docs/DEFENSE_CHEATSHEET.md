# Шпаргалка к защите ЛР №2 — объяснение простыми словами

## Выступление на 60–90 секунд

> Я взял заготовку Notes из ветки `starter` и закрыл основные Android IPC-точки входа. В AndroidManifest явно указал `android:exported` у компонентов. Снаружи доступна только главная Activity для launcher/deep link и провайдер заголовков, который защищён разрешением уровня `signature`. Ресивер кнопки уведомления и FileProvider закрыты. Для фото применил системный Photo Picker без разрешений ко всей галерее; разрешение на уведомления запрашивается по нажатию «Напомнить», отказ не мешает заметкам. Deep link `notes://note/id` строго проверяется, а существование id дополнительно проверяется в Room. У уведомлений явные immutable PendingIntent. Экспорт файла идёт через `content://` и временный URI-грант. Другой клиент получает только `_id` и `title`, если его APK подписан тем же сертификатом; посторонний не может читать или изменять данные. На моём эмуляторе скрипт преподавателя показывал 18 PASS, 0 FAIL, но случай с другим сертификатом я демонстрирую отдельно.

Это опорный текст; не выдавайте его за личные результаты без демонстрации экрана.

## Презентация на 5 минут: порядок действий

**1. Покажите манифест.** `notes/src/main/AndroidManifest.xml` — MainActivity exported true для deep links; ReminderActionReceiver false; FileProvider false + grantUriPermissions; TitlesProvider true + `permission=...READ_NOTES`. Объясните, что именно экспортированное доступно извне, но провайдер ограничен подписью.

**2. Покажите Photo Picker и напоминание.** Сохраните заметку, выберите фото без общего доступа к медиа; нажмите «Напомнить», покажите rationale, настройку разрешения, через 10 сек — уведомление, затем «Готово».

**3. Откройте deep link.** Покажите `adb shell am start ... -d 'notes://note/1'`, затем 999999 и abc. Укажите `NoteDeepLink.parse`, `NoteViewModel.load`, экран notFound.

**4. Покажите файл.** `NoteExporter` → `FileProvider.getUriForFile` → `ACTION_SEND` → `FLAG_GRANT_READ_URI_PERMISSION`; затем посторонний `content read` от shell получает отказ.

**5. Покажите клиент.** В `client/TitlesClient` `ContentResolver.query`, в Notes `TitlesProvider.query` и `signature` в манифесте. Клиент с таким же ключом видит заголовки; чужой ключ не получает доступ. Скрипт ADB сам по себе другого сертификата не имитирует.

**6. Покажите `scripts/check.sh all`:** проверьте `PASS/FAIL`, вывод `ИТОГО: ...` и фактический файл `docs/evidence/check-all.txt`.

## Вопросы преподавателя и короткие ответы

| Вопрос | Краткий ответ |
|---|---|
| Что такое IPC? | Взаимодействие процессов; у нас клиент вызывает ContentProvider другого APK через Binder/ContentResolver. |
| Что такое компонент Android? | Activity, Service, BroadcastReceiver, ContentProvider — системные точки входа в приложение. |
| Что делает `android:exported`? | Управляет доступностью компонента для чужих пакетов; не заменяет проверку входных данных. |
| Почему `MainActivity` экспортирована? | Иначе launcher и сторонняя deep-link ссылка не смогут её открыть. |
| Почему `TitlesProvider` экспортирован? | Его должен вызвать другой APK; доступ всё равно ограничен signature-разрешением. |
| Почему FileProvider `exported=false`? | Чужой пакет не должен открывать его произвольно; доступ к URI выдаётся точечно через грант. |
| Что такое `authority`? | Уникальное имя ContentProvider в `content://...`; Android использует его для маршрутизации вызова. |
| Чем `content://` лучше `file://`? | Провайдер контролирует, какой файл отдаёт, а Android выдаёт временное право чтения конкретного URI. |
| Что такое URI-grant? | Временное разрешение получателю Intent читать переданный `content://` URI. |
| `signature` — это проверка пароля? | Нет, Android сравнивает сертификаты подписи APK приложения-владельца и вызывающего клиента. |
| Может ли стороннее приложение просто написать `<uses-permission>`? | Написать может, но Android не выдаст `signature` без совпадения сертификата. |
| Почему нельзя доверять имени пакета? | Имя/строка — не криптографическое подтверждение происхождения, сертификат проверяет ОС. |
| Почему клиент знает о провайдере, если Notes хранит БД отдельно? | Он знает публичный URI, не SQLite-файл; обращается через ContentResolver. |
| Почему отдаёте только заголовки? | Принцип минимальных данных: запрос SQL выбирает id/title, body/photo не доступны. |
| Почему нельзя insert/delete в TitlesProvider? | Провайдер задуман read-only; методы модификации бросают UnsupportedOperationException. |
| Что происходит при `notes://note/abc`? | Парсер отклоняет id, до Room дело не доходит; безопасное сообщение/нет перехода. |
| Что при `notes://note/999999`? | Синтаксис допустим, но Room не находит запись; ViewModel ставит notFound, форма недоступна. |
| Почему `toLongOrNull()`, а не `toLong()`? | Чтобы мусор и переполнение не вызывали NumberFormatException. |
| Почему проверяется `encodedPath`? | Чтобы не разрешать неоднозначные кодированные сегменты и лишние части пути. |
| Что такое Intent? | Сообщение Android-компоненту: действие, данные URI, extras и адрес получателя. |
| Явный и неявный Intent? | Явный указывает конкретный компонент, неявный — только действие/категории. |
| Для чего PendingIntent? | Это передаваемый системе объект, позволяющий позже выполнить действие от имени создавшего приложения. |
| Почему `FLAG_IMMUTABLE`? | Получатель не может подменить содержимое и направить действие на другой компонент/данные. |
| Почему одновременно `UPDATE_CURRENT`? | Владелец PendingIntent обновляет собственное содержимое, не передавая право изменить его получателю. |
| Почему action проверяется в Receiver? | Даже внутренний ошибочный вызов с другим действием не должен отменить напоминание. |
| Почему нет READ_MEDIA_IMAGES? | Photo Picker выдаёт доступ только к выбранной пользователем фотографии. |
| Когда просится POST_NOTIFICATIONS? | При первой попытке поставить напоминание на Android 13+, а не при старте. |
| Что при отказе в POST_NOTIFICATIONS? | Напоминание не показывается, но все остальные операции с заметками продолжаются. |
| Почему канал `reminders`? | Android 8+ требует NotificationChannel; имя канала задано в ТЗ и в коде. |
| Что такое Room? | Библиотека поверх SQLite с DAO и Entity; упрощает типизированную работу с таблицами. |
| Что такое `Flow`? | Поток обновлений данных; список автоматически обновляется после изменений в Room. |
| Чем ViewModel отличается от Composable? | ViewModel хранит состояние/логику; Composable отображает данные и передаёт действия пользователя. |
| Для чего `appContainer`? | Один объект для БД, репозитория и сервисов вместо ручного создания их на каждом экране. |
| Чем AndroidTest отличается от скрипта check.sh? | AndroidTest выполняется от приложения/тестового процесса; check.sh атакует компонент извне через ADB shell. |
| Почему `Broadcast completed` не признак уязвимости? | Команда могла завершиться, а private receiver не выполнялся; нужна проверка Logcat и состояния. |
| Что такое merged manifest? | Итоговый манифест APK после объединения вашего XML и манифестов зависимостей. |
| Почему 18 PASS недостаточно для всей защиты? | Часть сценариев (подпись чужого APK, клики UI, Photo Picker) проверяется только вручную. |
| Где бонус HTTPS App Links? | Не выполнен: нужен реальный HTTPS-домен и проверяемый assetlinks.json, `notes://` — это обычный deep link. |

## Где быстро показать конкретную строку

- `NotesApp.kt` — создание канала `reminders`.
- `NoteDeepLink.kt` — проверка scheme/host/encodedPath/числа.
- `NoteViewModel.kt` — `repository.get`, `notFound` и запрет `save`.
- `ReminderPermission.kt` — runtime permission, rationale и счётчик отказов.
- `ReminderScheduler.kt` — `PendingIntent.FLAG_IMMUTABLE`.
- `ReminderActionReceiver.kt` — сравнение `ACTION_DONE` и noteId.
- `NoteExporter.kt` / `ShareNote.kt` — txt, content URI и грант.
- `file_paths.xml` — единственный разрешённый каталог.
- `TitlesProvider.kt` — белый список колонок и запрет записи.
- `TitlesClient.kt` — реальный ContentResolver.query.
- `notes/src/main/AndroidManifest.xml` — `exported`, `signature`.

## Если преподаватель спросит про ограничения

Не скрывайте их: напоминание в текущем коде не сохраняется после уничтожения процесса; удаление из экрана списка не вызывает отмену ранее запланированного напоминания; копии выбранных фотографий автоматически не удаляются при смене/удалении; «bonus» HTTPS App Links не реализован. Эти ограничения не отменяют реализованные механизмы безопасности, но показывают границы текущей учебной версии.
