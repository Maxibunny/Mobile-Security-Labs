# Защита лабораторной №2 — конспект по пунктам задания

Это подсказки для объяснения собственного кода. Пометки `PASS` ставятся **только после** фактического прогона `scripts/check.sh` на эмуляторе.

## ipc-1. Манифест и exported

**Что защищаем?** Android-компонент — вход в процесс. `exported=true` позволяет другим приложениям обращаться к нему, если не поставлены дополнительные барьеры. `exported=false` означает, что чужим приложениям компонент недоступен напрямую. `MainActivity` публична для LAUNCHER и VIEW. `TitlesProvider` публичен, но требуется `signature`-permission. Receiver и FileProvider закрыты. Из разрешений Notes просит только `POST_NOTIFICATIONS`.

**Что такое merged manifest?** Манифест, полученный после объединения собственного XML с XML зависимостей AndroidX. Именно он войдёт в APK. ProfileInstallReceiver удалён через `tools:node="remove"`, потому что не относится к функциям лабораторной и не должен быть лишней экспортированной точкой входа. Проверка: `bash scripts/check.sh manifest`.

## ipc-2. Минимальные runtime permissions

**Почему разрешение запрашивается только при нажатии?** Пользователь должен понимать, для чего требуется доступ. На API 33+ есть `POST_NOTIFICATIONS`, на API 26–32 такого runtime-разрешения нет. Первое объяснение даётся AlertDialog. После отказа приложение работает без уведомления; после второго предлагаются настройки. `shouldShowRequestPermissionRationale` учитывается при повторной попытке.

**Почему Photo Picker без разрешений?** Системный выбор сам предоставляет временный `content://` URI только одного выбранного снимка, `PhotoStore` делает собственную приватную копию.

## ipc-3. Deep link

**Как открыть?** `adb shell am start -a android.intent.action.VIEW -d 'notes://note/1'`. Host должен быть `note`, схема `notes`; единственный сегмент пути — положительное десятичное Long без дополнительных сегментов/параметров. `toLongOrNull()` исключает crash при переполнении, `Room.getById` проверяет существование. Для отсутствующего id — отдельный `notFound` экран, без Save/Delete.

**Почему нельзя просто довериться Uri?** Любое приложение может отправить ACTION_VIEW. Корректный синтаксис URI не гарантирует, что id есть в БД.

## ipc-4. PendingIntent и BroadcastReceiver

**Что такое PendingIntent?** Сохранённое право выполнить определённый Intent позднее от имени нашего приложения. Нажатие по телу уведомления идёт в `MainActivity`, по «Готово» — в неэкспортированный `ReminderActionReceiver`. Оба Intent явные и имеют `FLAG_IMMUTABLE`.

**Что делает Receiver?** Проверяет `ACTION_DONE`, наличие и корректность `EXTRA_NOTE_ID`; отменяет ожидающий Job и выданное уведомление. При удалении самой заметки ViewModel также отменяет её напоминание, чтобы не оставить уведомление с уже удалённым ID. В logcat пишется точная строка `DONE received for note <id>`. Посторонняя команда `am broadcast` эту строку не создаёт.

## ipc-5. FileProvider

**Почему нельзя передавать File или file://?** Чужое приложение не имеет прав читать `cacheDir`; Android ограничивает передачу `file://`. `FileProvider` превращает файл в `content://` и может временно выдать право на чтение через `FLAG_GRANT_READ_URI_PERMISSION`. В `file_paths.xml` есть только `cacheDir/exports/`, экспорт запрещён.

**Почему shell получает отказ, а выбранное приложение читает?** Chooser выдаёт read-grant конкретному выбранному получателю, shell такой grant не получал.

## ipc-6. Provider для своих

**Что такое ContentProvider?** Android Binder-интерфейс для структурированных данных. `TitlesProvider` отдаёт только `_id` и `title` для URI `/notes`. `UriMatcher` сверяет путь, `MatrixCursor` формирует результат, данные берутся из Room через `titlesBlocking()`.

**Где реально проверяется доступ?** ОС проверяет объявленное `edu.androidsec.notes.permission.READ_NOTES` уровня `signature` перед вызовом провайдера. `Binder.getCallingUid()` и `callingPackage` записываются только как диагностические данные. `android:permission` закрывает чтение **и запись**, а `insert/update/delete` ещё и отвергаются в коде.

**Что изменится, если клиент подписать новым сертификатом?** Permission больше не выдаётся, `query` завершается `SecurityException`.

## Что покажем на защите — последовательность

1. `bash scripts/check.sh all`; показать реальное `FAIL=0` **после его получения**, раскрыть `merged manifest`.
2. Запустить `notes://note/1`, `999999`, `abc`, пустой id.
3. Дважды отказать в уведомлениях, открыть настройки, затем разрешить и получить уведомление.
4. Сравнить лог при прямом `am broadcast` и при настоящем нажатии «Готово».
5. Отправить TXT в другую программу, показать отказ от `adb content read`.
6. Открыть `:client` с тем же ключом, потом с другим ключом — продемонстрировать отказ.
